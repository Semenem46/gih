# 🚀 Runbook: как поднять бота с нуля

Эта инструкция — пошаговая. Делай по порядку, ничего не пропускай.

---

## 0. Что мы запускаем

Три процесса, каждый в своём окне терминала (`tmux`/`screen`/SSH-сессии):

| # | Процесс | Что делает |
|---|---|---|
| A | **chat_discoverer_apex.py** | Ищет новые TG-чаты по нишам и добавляет в БД |
| B | **parser_apex_ai.py** | Индексер: читает чаты из БД и складывает сообщения в корпус (с FTS5) |
| C | **bot/bot.py** | Telegram-бот для клиентов: лид-магнит + Разбор ниши + подписка |

Всё работает поверх **общей БД** `apex_ai.db` рядом с этими файлами.

---

## 1. Сервер

Нужен Linux-сервер (VPS), где будет крутиться 24/7.
- 1 ядро, 1 ГБ RAM, 10 ГБ диска — хватит на старте
- Ubuntu 22.04+ или Debian 12+
- Python **3.11** или новее

Проверка:
```bash
python3 --version  # должно быть >= 3.11
```

Если меньше — `sudo apt install python3.11 python3.11-venv` (или ставь pyenv).

## 3. Telethon-сессия (главное!)

**Это самый важный шаг.** Парсеру и разведчику нужен авторизованный TG-аккаунт.

Используй **отдельный** TG-аккаунт (не свой основной!), потому что:
- TG может его залочить за «много чтения»
- Если что — потеряешь свой основной

### 3.1. Купи виртуальный номер
- [sms-activate.org](https://sms-activate.org) — берёшь номер РФ за 30–80 ₽
- Или возьми отдельную физическую SIM (надёжнее, но дороже)

### 3.2. Зарегистрируй на нём аккаунт
В обычном Telegram-приложении на телефоне → новый аккаунт → код по SMS на купленный номер.

### 3.3. Сгенерируй сессию
**Локально на своём ноуте** (не на сервере!):

```bash
pip install telethon
python3 -c "
from telethon import TelegramClient
client = TelegramClient('apex_discoverer_v.session', 37992056, '60613234526a75894811075d80c5b7f3')
client.start()
print('Session created!')
"
```

Скрипт спросит номер телефона и SMS-код. После этого появится файл `apex_discoverer_v.session` — это и есть авторизация.

### 3.4. Загрузи .session на сервер
```bash
scp apex_discoverer_v.session user@server:/opt/leadbot/
```

## 4. Создать `.env` для бота

```bash
cd /opt/leadbot/bot
cp .env.example .env
nano .env
```

Заполни так:

```ini
# Bot Token — от @BotFather (создай нового бота)
BOT_TOKEN=<YOUR_BOT_TOKEN>

# Твой TG user_id — узнать через @userinfobot
ADMIN_IDS=8128303065

# Контактный username для кнопок (БЕЗ @)
AUTHOR_NAME=Никита
AUTHOR_USERNAME=stendapik
SUPPORT_USERNAME=stendapik

# Опционально — кнопки в follow-up
LINK_BOOK_CALL=
LINK_CASES=
LINK_CHANNEL=

# Drip-кампания (минуты после получения файла)
DRIP_SCHEDULE_MINUTES=30,1440,4320,10080

LOG_LEVEL=INFO
```

**Где взять BOT_TOKEN:**
1. В TG найди `@BotFather` → `/newbot` → имя → username (`*_bot`)
2. BotFather пришлёт токен типа `1234567:AAA...` — скопируй сюда

## 6. Запуск (3 окна tmux)

Поставь tmux: `sudo apt install tmux`

Запусти его: `tmux new -s leadbot`

Внутри:
- **Ctrl+B затем %** — split вертикально
- **Ctrl+B затем "** — split горизонтально
- **Ctrl+B затем стрелки** — переключение между окнами
- **Ctrl+B затем D** — отключиться (tmux продолжает работать)
- `tmux attach -t leadbot` — вернуться

### Окно A: Разведчик чатов
```bash
cd /opt/leadbot
source venv/bin/activate
python3 chat_discoverer_apex.py
```

### Окно B: Индексер
```bash
cd /opt/leadbot
source venv/bin/activate
python3 parser_apex_ai.py
```
Этот процесс пишет в БД, **никаких алёртов про каждый лид**, только статистика раз в час админу.

**Первый запуск с пустой БД — это долго.** На 1400 чатах индексация ~3–6 часов. Потом он крутится по кругу с лимитом 30 чатов/цикл, проверяя свежее.

### Окно C: Бот
```bash
cd /opt/leadbot/bot
source ../venv/bin/activate
python3 bot.py
```

В логах должно появиться:
```
Drip scheduler started (poll every 60 sec)
Run polling for bot @your_bot_name
```

## 7. Проверка что всё работает

### 7.1. Индексер пишет в корпус?
```bash
cd /opt/leadbot
sqlite3 apex_ai.db "SELECT COUNT(*) FROM messages_corpus;"
```
Через час должны быть тысячи строк.

### 7.2. Бот отвечает?
В Telegram: открой своего бота → `/start` → должен прийти лид-магнит и кнопки.

### 7.3. Тест Разбора ниши
1. В боте нажми **«🎯 Разбор моей ниши»**
2. Введи: `ремонт квартир в Москве`
3. Бот должен:
   - проанализировать (5 сек),
   - показать pre-check «найдено N сообщений»,
   - показать 1 бесплатный лид с кликабельной TG-ссылкой,
   - показать кнопки оплаты + написать в личку.

Если в БД ещё мало данных (индексер только запущен) — подожди час-два, попробуй снова.

## 8. Поток продажи (вручную)

Когда клиент жмёт **«💎 Подключить за 15 000 ₽/мес»**:

1. **Тебе** (как админу) приходит уведомление в личку:
   ```
   💎 Заявка на подписку Парсер Pro
   User ID: 12345678
   Имя: Иван Иванов
   Username: @ivan
   Ниша: ремонт квартир в Москве
   Активировать: /grant 12345678 30 ремонт квартир в Москве
   ```

2. Ты пишешь клиенту в личку (или ждёшь когда он напишет тебе через кнопку «✉️ Написать в личку»).

3. Договариваешься, получаешь 15 000 ₽ (карта / СБП / как удобно).

4. **В своём боте** копируешь и отправляешь команду:
   ```
   /grant 12345678 30 ремонт квартир в Москве
   ```
   Бот:
   - анализирует нишу,
   - сохраняет подписку на 30 дней,
   - **уведомляет клиента**: «Подписка активирована, лиды будут приходить в 10:00 МСК».

5. **Дальше всё автоматом.** Каждый день в 10:00 МСК cron перебирает активных подписчиков, ищет свежие лиды по их нише, помечает claim → шлёт клиенту в личку с кликабельной ссылкой.

## 9. Админ-команды (только для тебя)

В чате с ботом:
| Команда | Что делает |
|---|---|
| `/stats` | Статистика воронки (сколько лидов, кто получил файл) |
| `/export` | Выгрузить всех лидов в CSV |
| `/broadcast <текст>` | Рассылка по всем подписанным |
| `/grant <user_id> <дней> <ниша>` | Активировать подписку |
| `/revoke <user_id>` | Отключить подписку |
| `/subinfo <user_id>` | Узнать статус подписки |

## 10. Если упало

### Парсер вылетел с FloodWait
Это нормально, антифлуд встроен. Перезапусти.

### Бот ругается «no such table messages_corpus»
Парсер ещё не запускался / упал. Запусти его, он создаст таблицу.

### Клиент жалуется «бот не отвечает»
Проверь окно C (бот) — есть ли свежие логи. Если нет — `python3 bot.py` упал, перезапусти.

### Сервер перезагрузился
Все процессы умрут. Зайди в tmux (`tmux attach -t leadbot`) — там будет пусто. Запускай всё заново по шагу 6.

**Хочешь чтобы запускалось автоматически?** Сделаем systemd-юниты позже — но для старта tmux ок.
